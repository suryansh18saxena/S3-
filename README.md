# S3 Infrastructure — website

Marketing website for **S3 Infrastructure** (architects, interior designers and builders — Kodungaiyur, Chennai).
Next.js 16 (App Router) + TypeScript, exported as a fully static site: plain HTML/CSS/JS that any web host can serve.

> Content provenance and everything S3 still needs to confirm or supply is listed in **[CONTENT-REVIEW.md](CONTENT-REVIEW.md)**.

---

## Quick start

Requirements: **Node.js ≥ 20.9** (built and tested with Node 22.23 / npm 10.9). Building needs internet access once,
because `next/font` downloads the Google Fonts (Archivo, Manrope) at build time and self-hosts them.

```bash
npm install            # install dependencies
npm run dev            # dev server → http://localhost:3000
npm run build          # static export → ./out (also regenerates redirect files)
npm run preview        # serve ./out → http://localhost:4173
npm run check          # type-check + lint + production build
npm run check:links    # crawl the preview server for broken links/assets (run `npm run preview` first)
npm run images         # regenerate responsive images after editing scripts/media.config.mjs
```

## Deploying

`npm run build` writes the complete site to **`out/`**. Upload the *contents* of that folder.

| Host | How |
| --- | --- |
| **Hostinger / any Apache or LiteSpeed host** (current host) | Upload everything in `out/` (including the hidden **`.htaccess`**) to `public_html/`. The `.htaccess` adds the legacy-URL redirects, HTTPS + bare-domain canonicalisation, caching and security headers. |
| **Netlify / Cloudflare Pages** | Build command `npm run build`, publish directory `out`. The generated `_redirects` file is picked up automatically. |
| **Vercel** | Works as a static export. Redirects are *not* applied from `.htaccess`; port the list in `scripts/redirects.mjs` to `vercel.json` if you host there. |

URLs keep the WordPress-era trailing slash (`/about-us/`), so existing links and search results continue to resolve.
Old URLs that changed are 301-redirected — see `scripts/redirects.mjs` (single source of truth for both redirect files).

## Editing content

All copy, prices and contact details live in typed files under `src/content/`:

| File | What it holds |
| --- | --- |
| `site.ts` | Company name, director, phones, WhatsApp, email, address, service areas, navigation, social links (empty until verified) |
| `services.ts` | The seven disciplines, every service page's copy, design packages, cost-plus vs fixed-price table |
| `packages.ts` | **Turnkey package rates & specifications, exclusions, and the cost-calculator configuration** |
| `faqs.ts` | FAQ groups (also used for FAQPage structured data) |
| `typologies.ts`, `process.ts` | Building types and the six project stages |
| `testimonials.ts` | **Empty on purpose** — add only verified, client-approved reviews; the homepage section appears automatically |
| `projects.ts` | **Empty on purpose** — add real case studies; the Projects page renders them automatically |
| `media.ts` | Alt text for every image |

**Updating prices:** edit `packages.ts` (rates, `listRate`, specs) *and* `pricing.publishedOn` / `publishedLabel`. No component contains a price.

**Adding photography:** put the file in `assets/source/`, add an entry to `scripts/media.config.mjs` (use `local:` for S3's own photos),
run `npm run images`, then reference the key (with alt text in `src/content/media.ts`). Never label stock photography as an S3 project.

**Enquiry form backend (optional):** with no backend, the form validates input and then opens WhatsApp or the visitor's email
app with the enquiry pre-filled — and says so. To post enquiries to a form service instead (Formspree, Web3Forms, your own
endpoint accepting JSON), set `NEXT_PUBLIC_FORM_ENDPOINT` at build time. A success message is only shown on a 2xx response.

## Design & motion system

- **Type:** Archivo (variable, width 62–125 % — expanded cuts for the monumental "S3", numerals and labels) + Manrope for text
  + Instrument Serif italic for headline accents. Wrap words in `*asterisks*` in any `SectionHeading`, `PageHero`, `CtaBand`
  or `SplitFeature` title to set them in the serif (see `src/lib/accent.tsx`).
  Rupee (₹) and ≈ render from local system fonts via a tiny `local()`-only face, so prices never trigger extra font downloads.
- **Colour:** navy → sky palette refined from the logo (`#52B2E3` blue, `#77787A` grey), warm paper/stone neutrals.
  Tokens live in `src/app/globals.css` (`@theme`). Text colours meet WCAG AA.
- **Hero — "first light to lights on" (`src/components/home/`):**
  - *Entrance (pure CSS, from first paint):* on a drawing board with a title block and progress meter, the traced elevation
    draws itself, a liquid reveal floods it with the photograph, the giant "S3" rises behind the roofline and the headline
    assembles letter by letter. Repeat visits get a short entrance; phones skip the drawing stage (faster LCP).
  - *Scroll (GSAP, `HeroMotion.tsx`):* the hero holds (CSS `position: sticky`) while the sky turns to blue hour, stars come
    out, the house cross-fades to a version with lit windows (`hero-house-dusk`, generated from the same cut-out and loaded
    only after the entrance), the camera pushes in and "From first light / to lights on." rises; the studio section then
    slides over a darkening hero. The WebGL clouds take the dusk tint through `setSkyDusk()`.
  - *Pointer (desktop):* gentle depth parallax between sky, wordmark and house.
  - Reduced motion: the final daytime composition, no hold, no sequence.
- **Scroll motion:** `MotionProvider` drives Lenis smooth scrolling from GSAP's ticker and turns markup attributes into
  ScrollTrigger animations, so most sections stay Server Components:
  `data-reveal="up | fade | lines | words | chars | image | stagger | draw"`, `data-reveal-delay`, `data-parallax="0.12"`,
  `data-scrub="words"`, `data-odometer` (rolling digits — `ui/Odometer.tsx`), `data-marquee` (kinetic band that surges and
  leans with scroll velocity — `ui/Marquee.tsx`). Text splitting happens lazily as elements approach the viewport. Content is
  hidden only when JS runs and is revealed by a fallback timer if motion never boots; with JS disabled or reduced motion
  everything is visible.
- **Loading screen (`layout/SiteLoader.tsx`):** on the first page load of a session the company name assembles on a
  drawing board with a 0–100 count, then lifts away like a curtain; every page entrance waits for it. Skipped with reduced
  motion or JavaScript off (decided by the boot script in `app/layout.tsx`).
- **Header:** full-width bar with the original logo — transparent over the homepage hero (with a soft dark scrim), solid
  white once the page scrolls; a pill slides behind the hovered link, the phone button opens to show the number, and the
  call to action carries a periodic light sweep. Its size never changes on scroll.
- **Pointer effects (`motion/PointerEffects.tsx`, mouse/trackpad only):** the native cursor is never replaced. Cards can opt
  into a 3D tilt (`data-tilt`) and a glow that follows the pointer (`data-spotlight`). Buttons and nav links use a rolling
  label (`.roll`).
- **Signature sections:**
  - *Aperture* (`home/Aperture.tsx`): a pinned stage where a window cut into the drawing sheet opens to a full-bleed photograph
    while "Drawn." and "Built." are pushed apart — one CSS variable (`--a`) scrubbed by GSAP drives it all.
  - *Typology reel* (`home/TypologyReel.tsx`): each building type fills the screen in turn — the next photograph wipes up
    over the last as you scroll (which slides back into shadow) and its name rises in; a clickable index jumps between them.
    Stacked panels without motion.
  - *Spec sheet*: the studio facts as a blueprint table with rolling figures and dimension lines.
  - *Studio pillars* (`home/PillarPanels.tsx`): Design / Engineering / Execution as photo panels that open on hover or focus.
  - *Crossing tapes* (`home/DisciplinesBand.tsx`): two marquee bands crossing like site tape, surging with scroll speed.
  - *Expertise drum* (`home/ExpertiseDrum.tsx`): the seven disciplines printed on a 3D cylinder that turns with scroll (or a
    click); the discipline facing you drives a panel with a wiping photograph, counter and link. Reduced motion and no-JS get
    the plain index (`ExpertiseList.tsx`: titles fill with ink on hover, a preview follows the pointer).
  - *Construction sequence*: a pinned drawing builds through six project stages.
  - *Package deck* (`data-stack`): from md up the four packages stack as sticky cards; each card's header row stays visible
    as a tab (name, tier, rate), so the stack reads as an index, and covered cards dim.
  - *Two ways to build* (`home/TwoWays.tsx`): a draggable (and keyboard-operable) before/after comparison of separate firms
    vs S3's single team.
  - *Finale*: a headline whose letters swell under the pointer (variable-font weight and width); a footer wordmark that
    sketches its own outlines.
- **Page transitions:** React `<ViewTransition>` — the old page sinks back and dims while the new one wipes up, with the
  header anchored (no-op where unsupported).

### Libraries — what was used, and what was deliberately not

| Library | Decision |
| --- | --- |
| **GSAP 3.15** (+ ScrollTrigger, SplitText — all free since 3.13) | Used for scroll choreography, pinning, text reveals, pointer parallax. |
| **Lenis 1.3.26** | Used for smooth scrolling, synced to ScrollTrigger via GSAP's ticker; disabled for reduced motion. |
| **Motion 13.4.6** | Used for the mobile menu (enter/exit, staggered links), loaded on demand — most visitors never download it. The FAQ accordion uses a CSS `grid-template-rows` transition instead, which needs no library. |
| **Anime.js** | Not used: GSAP already covers SVG line drawing, so it would only duplicate an animation system. |
| **Vanta.js** | Evaluated and not used: last published September 2022 and depends on three.js (hundreds of KB) for one background. Replaced by a custom ~2 KB WebGL cloud shader with a CSS fallback. |
| **"StingTune"** | Identified as **StringTune** (`@fiddle-digital/string-tune`, by the Fiddle.Digital agency) — an attribute-driven smooth-scroll/parallax library. Not used: it overlaps Lenis + ScrollTrigger and would create two competing scroll systems. |

## Known limitations

- All photography is **representative stock** (Unsplash License) and is labelled as such; no genuine S3 project photos were available.
- The logo exists only as a 500 px raster; a vector original (SVG/AI/PDF) would render sharper at large sizes.
- No server-side form handling unless `NEXT_PUBLIC_FORM_ENDPOINT` is configured (see above).
- `.htaccess` redirects are written for Apache/LiteSpeed and were syntax-reviewed but not executed locally.
